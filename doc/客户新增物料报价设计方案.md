# 客户新增物料报价设计方案

## 1. 背景与目标

新增物料报价功能用于筛选指定时间范围内首次向指定客户交付的物料，并围绕这些物料完成报价、报价导出和最终定价。

这里的“新增物料”不是按物料建档时间判断，也不是全局物料首次出库，而是按“客户 + 物料”的首次实际交付时间判断。例如物料 A 在 2026-03 首次交付给客户甲，在 2026-06 首次交付给客户乙，那么物料 A 对客户乙来说仍属于 2026-06 的新增物料。

前端页面建议命名为“客户新增物料报价”。该名称比“物料报价”更准确，因为页面的核心入口是客户维度的新物料筛选和报价处理。

## 2. 业务边界

### 2.1 纳入统计的出库类型

建议只统计客户侧交付场景：

- 销售出库
- 样品出库
- 赠品出库

不建议纳入生产用料、报废、损耗、退货等非客户交付场景。

### 2.2 不调整现有价格提示逻辑

后续出库时仍复用当前客户物料价格提示功能，即继续读取现有 `material_price` 记录。新增报价模块只负责报价过程、报价导出和确认后写入最终价格，不改变出库页面当前取价提示方式。

## 3. 总体流程

```text
普通出库完成 / 极速出库创建完成
 -> 维护客户-物料首次交付记录
 -> 客户新增物料报价页面按客户和时间范围查询
 -> 对未报价或待定价物料创建报价单
 -> 选择详细报价或简单报价
 -> 保存草稿 / 提交报价
 -> 导出报价单
 -> 客户确认后转最终定价
 -> 写入现有 material_price
```

## 4. 数据模型设计

### 4.1 物料主档补充字段

`material` 可以补充全局首次交付字段，用于产品生命周期统计，但它不是客户新增物料报价的主要筛选依据。

```go
FirstDeliveryTime      int64  `json:"first_delivery_time" bson:"first_delivery_time"`             // 全局首次交付时间，按出库时间记录
FirstDeliveryOrderCode string `json:"first_delivery_order_code" bson:"first_delivery_order_code"` // 全局首次交付出库单号
```

更新策略：

- 为空时写入本次出库时间。
- 已存在但晚于本次出库时间时，更新为更早的出库记录。
- 已存在且早于本次出库时间时，不更新。


### 4.4 报价成本项结构

详细报价的成本项内嵌在 `material_quote.cost_items` 中。成本项必须包含 `index`，前端按 `category_code` 分区，再按 `index` 升序展示。

```go
type MaterialQuoteCostItem struct {
	Index        int     `json:"index" bson:"index"`                 // 成本项排序序号，前端按升序展示
	CategoryCode string  `json:"category_code" bson:"category_code"` // 成本类型编码：material、process、labor_equipment、quality、packing、freight、management、tooling、loss、tax、other
	CategoryName string  `json:"category_name" bson:"category_name"` // 成本类型名称：材料成本、加工工序成本、人工/设备成本等
	Name         string  `json:"name" bson:"name"`                   // 成本项名称，如原材料、折弯、焊接、打包费
	Enabled      bool    `json:"enabled" bson:"enabled"`             // 是否启用该成本项，未启用时不参与汇总
	Custom       bool    `json:"custom" bson:"custom"`               // 是否为手工新增的定制成本项
	Quantity     float64 `json:"quantity" bson:"quantity"`           // 数量、工时、次数或摊销数量
	Unit         string  `json:"unit" bson:"unit"`                   // 单位，如 kg、小时、次、件
	UnitCost     float64 `json:"unit_cost" bson:"unit_cost"`         // 单位成本
	Amount       float64 `json:"amount" bson:"amount"`               // 成本金额，通常为 quantity * unit_cost，也允许手工调整
	Remark       string  `json:"remark" bson:"remark"`               // 成本项备注
}
```

推荐成本类型：

| category_code | category_name | 说明 |
| --- | --- | --- |
| material | 材料成本 | 原材料、辅料、材料损耗 |
| process | 加工工序成本 | 下料、折弯、焊接、机加工、表面处理、外协 |
| labor_equipment | 人工/设备成本 | 人工工时、设备工时、调机费、换模费 |
| quality | 质量成本 | 检验、返工预估、报废预估 |
| packing | 包装成本 | 清点、标签、打包、纸箱、托盘 |
| freight | 物流成本 | 运费、装卸费 |
| management | 管理成本 | 管理费、财务成本、办公摊销 |
| tooling | 模具/治具摊销 | 模具费、治具费、按批量摊销 |
| loss | 损耗成本 | 生产损耗、材料损耗、异常损耗 |
| tax | 税费 | 税率、税额 |
| other | 其他成本 | 手工新增的定制成本项 |

转最终定价时：

- 校验报价单存在且未作废。
- 使用报价单中的客户和物料写入 `material_price`。
- 更新 `material_quote.status = priced`。
- 更新 `customer_material_delivery.quote_status = priced`、`latest_price`、`latest_quote_id`。
- 不调整现有出库价格提示逻辑。

## 6. 前端页面设计

### 6.1 页面位置与名称

建议在前端物料管理模块下新增页面：

```text
web/src/views/material/quote/index.vue
```

页面菜单名称建议：`客户新增物料报价`

如果菜单宽度有限，可显示为：`新增物料报价`

### 6.2 页面布局

页面建议采用工作台式布局：

```text
顶部筛选区
  客户、首次交付日期范围、报价状态、物料名称、物料型号、查询、重置、导出

中部新增物料表格
  首次交付日期、客户、物料名称、型号、规格、单位、首次出库单号、首次交付数量、报价状态、最新报价、操作

右侧或弹窗报价编辑区
  物料基础信息
  报价方式切换：详细报价 / 简单报价
  成本分区表单
  汇总区：成本合计、利润率、税率、最终报价
  保存草稿、提交报价、导出报价、转最终定价
```

### 6.3 成本项展示规则

详细报价成本项在前端按类型分区展示：

```text
材料成本
加工工序成本
人工/设备成本
质量成本
包装成本
物流成本
管理成本
模具/治具摊销
损耗成本
税费
其他成本
```

每个分区内按 `index` 升序展示。

每个成本项支持：

- 启用 / 停用
- 编辑数量、单位、单位成本、金额、备注
- 手工新增定制成本项
- 删除成本项
- 调整 `index` 排序

`enabled = false` 的成本项不参与 `total_cost` 汇总，但仍保留在报价单中，方便后续重新启用。

`custom = true` 的成本项表示用户手工新增，允许删除。系统预置成本项也可以允许删除，但更建议默认只停用，避免误删常用模板项。

### 6.4 详细报价计算规则

```text
单项金额 = quantity * unit_cost
成本合计 = sum(enabled cost_items.amount)
利润金额 = 成本合计 * profit_rate
税额 = (成本合计 + 利润金额) * tax_rate
最终报价单价 = 成本合计 + 利润金额 + 税额
报价总金额 = 最终报价单价 * quantity
```

如果业务允许手工覆盖最终报价，则前端应标记为“手工调整”，后端仍保存 `final_price`。

### 6.5 简单报价规则

简单报价只展示少量字段：

- 报价数量
- 简单报价单价
- 有效期
- 备注

保存时：

```text
quote_mode = simple
simple_price = 输入单价
final_price = 输入单价
total_amount = 输入单价 * quantity
cost_items = []
```

### 6.6 报价导出

报价导出建议支持当前报价单导出，格式可先使用 Excel，后续再扩展 PDF。

导出内容：

- 报价单号
- 客户信息
- 物料信息
- 报价方式
- 成本明细分区
- 成本合计、利润、税额、最终报价
- 有效期
- 备注

详细报价导出应保留成本类型分区和 `index` 排序。

## 7. 后端触发点

### 7.1 普通出库

普通出库在出库单状态成功变更为 `已出库` 并写入 `departure_time` 后维护首次交付记录。

当前对应逻辑位于：

```text
api/internal/logic/outbound/departureLogic.go
```

建议在出库单更新成功后：

- 查询该出库单的 `outbound_material` 明细。
- 对每个物料维护 `customer_material_delivery`。
- 同步维护 `material.first_delivery_time`。

### 7.2 极速出库

极速出库创建时已经直接生成完成态出库单和明细，应在同一个事务内维护首次交付记录。

当前对应逻辑位于：

```text
api/internal/logic/outbound/fastDepartureLogic.go
```

建议在插入出库单和出库明细后、提交事务前维护：

- `customer_material_delivery`
- `material.first_delivery_time`

### 7.3 历史数据回填

上线前需要执行一次历史回填：

```text
从 outbound_order 查询客户侧已出库/已签收单据
 -> 关联 outbound_material
 -> 按 customer_id + material_id 聚合最早 departure_time
 -> 写入 customer_material_delivery
 -> 按 material_id 聚合全局最早 departure_time
 -> 写入 material.first_delivery_time
```

如果后续允许修改出库时间或删除已出库单据，需要提供重算脚本或后台修复入口，避免首次交付记录与事实单据不一致。

## 8. 状态流转

### 8.1 客户新增物料报价状态

```text
unquoted 未报价
 -> quoting 报价中
 -> quoted 已报价
 -> priced 已定价
```

### 8.2 报价单状态

```text
draft 草稿
 -> submitted 已提交
 -> quoted 已报价
 -> priced 已定价

任意未定价状态
 -> void 作废
```

## 9. 实施顺序建议

1. 新增 `customer_material_delivery` 和 `material_quote` 模型结构体，字段全部补充中文注释。
2. 在 `ServiceContext` 增加对应 Mongo 集合和索引。
3. 实现普通出库、极速出库维护首次交付记录的公共 helper。
4. 实现历史回填脚本或一次性管理接口。
5. 实现客户新增物料分页接口。
6. 实现报价单保存、详情、分页、提交、作废接口。
7. 实现报价导出接口。
8. 实现报价转最终定价，写入现有 `material_price`。
9. 前端新增 `客户新增物料报价` 页面和 `material/quote` API 类型。
10. 前端实现详细报价分区、成本项启用/停用、定制项新增/删除、按 `index` 排序。

## 10. 关键结论

- “新增物料”应定义为“客户 + 物料 + 首次交付时间”，不能只依赖物料主档。
- 报价过程应由 `material_quote` 承载，最终价格仍沉淀到现有 `material_price`。
- 详细报价成本项内嵌在报价单中，并通过 `category_code` 分区、`index` 排序。
- 前端页面建议命名为“客户新增物料报价”，展示筛选、报价、导出和转定价完整闭环。
- 当前客户物料价格提示功能暂不调整，避免扩大出库流程改造范围。
